Лабораторная работа 3

Упаковка FastAPI в Docker · Парсер через HTTP · Celery + Redis

Подзадача 1: Docker + Compose (70%) Подзадача 2: HTTP-вызов парсера (70%) Подзадача 3: Очередь Celery (100%)

Цель и задачи

Цель — научиться упаковывать FastAPI-приложение в Docker, интегрировать парсер данных с базой данных и вызывать парсер через API и очередь задач.

🐳 Подзадача 1

Dockerfiles для API и парсера. docker-compose.yml объединяет все сервисы в единую сеть.

🔗 Подзадача 2

Эндпоинт в основном API вызывает parser-сервис по HTTP и возвращает результат клиенту.

⚡ Подзадача 3

Celery-воркер обрабатывает задачи из Redis-очереди. Клиент не ждёт результата.

Архитектура системы

Все сервисы работают в одной Docker-сети. Связь между ними — по именам контейнеров (db, redis, parser).

Подзадача 1 — Docker и Compose

Docker позволяет упаковать приложение со всеми зависимостями в изолированный контейнер. Docker Compose управляет несколькими контейнерами как единой системой.

Dockerfile — основное API (lab1)

FROM python:3.13-slim

# -u: логи сразу в stdout (видно в docker logs), без .pyc в образе
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

WORKDIR /app

# psycopg2-binary приезжает готовым колесом, поэтому gcc и libpq-dev
# в образе не нужны — меньше размер и меньше поверхность атаки.
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Контейнер работает не от root
RUN useradd --create-home --uid 1000 appuser \
    && chown -R appuser:appuser /app
USER appuser

EXPOSE 8000

HEALTHCHECK --interval=10s --timeout=5s --start-period=20s --retries=5 \
    CMD python -c "import urllib.request as u; u.urlopen('http://127.0.0.1:8000/', timeout=3)" || exit 1

# Миграции выполняет отдельный сервис `migrate` из docker-compose,
# поэтому здесь только запуск сервера.
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

Подзадача 2 — Парсер-сервис

Отдельное FastAPI-приложение (lab3/parser/main.py), запускаемое в контейнере parser. Принимает URL, загружает HTML, извлекает <title> и сохраняет в БД как задачу.

@app.post("/parse", response_model=ParseResponse)
def parse_and_save(request: ParseRequest) -> ParseResponse:
    # 1. Загрузить страницу
    response = requests.get(request.url, timeout=15)
    soup = BeautifulSoup(response.text, "html.parser")
    title = soup.title.string.strip() if soup.title else "Без заголовка"

    # 2. Сохранить в БД (таблица tasks из ЛР1)
    conn = get_db_connection()
    user_id = get_or_create_parser_user(conn)
    task_id = save_task_to_db(conn, user_id, title, request.url)
    conn.close()

    return ParseResponse(url=request.url, title=title, task_id=task_id)

Синхронный эндпоинт в основном API

API принимает запрос от клиента, проксирует его в parser-контейнер и возвращает результат. Клиент ждёт завершения.

POST /parser/parse
Body: {"url": "https://python.org"}
Response: {"url": "...", "title": "...", "task_id": 42, "message": "..."} 
@router.post("/parse")
def parse_sync(request: ParseRequest, _: User = Depends(get_current_user)):
    response = httpx.post(
        f"{settings.parser_url}/parse",   # http://parser:8001/parse
        json={"url": request.url},
        timeout=30.0,
    )
    return response.json()  # возвращает результат парсинга клиенту

Подзадача 3 — Celery + Redis (очередь задач)

Celery — распределённая очередь задач. При получении запроса API кладёт задачу в Redis, а Celery-воркер обрабатывает её в фоне. Клиент не блокируется.

Конфигурация Celery (app/celery_app.py)

from celery import Celery
from app.config import settings

celery_app = Celery(
    "timemanager",
    broker=settings.celery_broker_url,    # redis://redis:6379/0
    backend=settings.celery_result_backend,
)

celery_app.conf.update(
    task_serializer="json",
    task_routes={
        "app.tasks.parse_url_task": {"queue": "parsing"},
    },
)

Celery-задача (app/tasks.py)

@celery_app.task(bind=True, max_retries=3, default_retry_delay=5)
def parse_url_task(self, url: str) -> dict:
    """Вызывает parser-сервис. При ошибке — повторяет до 3 раз."""
    try:
        response = httpx.post(
            f"{settings.parser_url}/parse",
            json={"url": url},
            timeout=30.0,
        )
        return response.json()
    except httpx.HTTPError as exc:
        raise self.retry(exc=exc)  # автоматический retry

Асинхронные эндпоинты

POST /parser/parse/async
Ставит задачу в очередь. Возвращает task_id немедленно.
GET /parser/task/{task_id}
Проверить статус задачи: PENDING → STARTED → SUCCESS / FAILURE
@router.post("/parse/async")
def parse_async(request: ParseRequest, _=Depends(get_current_user)):
    task = parse_url_task.delay(request.url)  # кладём в очередь
    return {
        "task_id": task.id,
        "status": "queued",
        "message": f"Проверьте: GET /parser/task/{task.id}",
    }

@router.get("/task/{task_id}")
def get_task_status(task_id: str, _=Depends(get_current_user)):
    result = parse_url_task.AsyncResult(task_id)
    return {
        "task_id": task_id,
        "status": result.status,             # PENDING / SUCCESS / FAILURE
        "result": result.result if result.successful() else None,
    }

Как запустить

# Перейти в папку lab3
cd lab3

# Запустить все сервисы (первый раз строит образы ~2-3 минуты)
docker compose up --build

# Сервисы после запуска:
# API + Swagger:  http://localhost:8000/docs
# Parser:         http://localhost:8001/docs
# PostgreSQL:     localhost:5435
# Redis:          localhost:6380

Тестирование через Swagger (localhost:8000/docs)

1. POST /auth/register — зарегистрироваться
2. POST /auth/login — получить JWT токен
3. Нажать Authorize 🔒 в Swagger, вставить токен
4. POST /parser/parse — синхронный парсинг
5. POST /parser/parse/async — поставить в очередь
6. GET /parser/task/{task_id} — проверить статус

⚠ Важно: Celery-воркер запускается из того же образа что и API, но с командой celery -A app.celery_app worker. Это стандартная практика в production.

Обзор подходов

🧵 Threading

Потоки разделяют одну память процесса. Переключение дешёвое, но GIL ограничивает параллелизм для CPU-bound задач. Хорош для I/O-bound работы.

🔀 Multiprocessing

Каждый процесс — отдельный интерпретатор Python с собственной памятью. Обходит GIL. Лучший выбор для CPU-bound задач. Дороже по памяти.

⚡ Async / Await

Однопоточная кооперативная многозадачность. Event loop переключается между корутинами когда они ждут I/O. Максимально эффективен для сетевых задач.

GIL — Global Interpreter Lock

GIL — мьютекс внутри CPython, который позволяет только одному потоку одновременно исполнять байткод Python. Это решение упрощает управление памятью, но ограничивает параллелизм.

⚠ Важно: GIL освобождается во время I/O операций (сеть, диск). Поэтому threading эффективен для I/O-bound задач, но бесполезен для CPU-bound — там нужен multiprocessing.

Задача 1 — Вычисление суммы чисел 1..N

Каждая программа разбивает диапазон [1, N] на равные части и вычисляет частичные суммы параллельно. Результаты объединяются и проверяются по формуле N*(N+1)/2.

Используется N = 10_000_000 (10 млн) для демонстрации. Код аналогичен для N = 10_000_000_000_000 — только дольше выполняется.

🧵 Threading — вычисление суммы

Потоки разделяют память — частичные суммы записываются в общий словарь через Lock. Из-за GIL потоки не выполняются по-настоящему параллельно для CPU-bound вычислений.

def calculate_sum(start: int, end: int, thread_id: int) -> None:
    partial = sum(range(start, end + 1))
    with lock:                     # защита от race condition
        results[thread_id] = partial

def main(n: int = N_DEMO) -> float:
    chunk = n // NUM_THREADS
    threads = []
    for i in range(NUM_THREADS):
        start = i * chunk + 1
        end = (i + 1) * chunk if i < NUM_THREADS - 1 else n
        t = threading.Thread(target=calculate_sum, args=(start, end, i))
        threads.append(t)

    t0 = time.perf_counter()
    for t in threads: t.start()
    for t in threads: t.join()    # ждём завершения всех потоков

    total = sum(results.values())
    return time.perf_counter() - t0

⚡ Async — вычисление суммы

Чистый asyncio не поможет с CPU-bound задачами. Решение: loop.run_in_executor(ProcessPoolExecutor) — задачи отправляются в процессы, а event loop ожидает их асинхронно через await.

def calculate_sum(start: int, end: int) -> int:
    return sum(range(start, end + 1))   # синхронная функция для executor

async def async_calculate_sum(executor, start, end) -> int:
    loop = asyncio.get_running_loop()
    # run_in_executor не блокирует event loop
    return await loop.run_in_executor(executor, calculate_sum, start, end)

async def main_async(n: int = N_DEMO) -> float:
    with ProcessPoolExecutor(max_workers=NUM_WORKERS) as executor:
        tasks = [async_calculate_sum(executor, start, end)
                 for start, end in chunks]
        t0 = time.perf_counter()
        partial_sums = await asyncio.gather(*tasks)  # все параллельно

    total = sum(partial_sums)
    return time.perf_counter() - t0

🧵 Threading — парсинг

Каждый URL парсится в отдельном потоке. Это эффективно: пока один поток ждёт ответа от сервера (I/O), GIL освобождается и другие потоки работают. Каждый поток создаёт своё соединение с БД.

def parse_and_save(url: str) -> None:
    response = requests.get(url, timeout=10)
    soup = BeautifulSoup(response.text, "html.parser")
    title = soup.title.string.strip() if soup.title else "Без заголовка"

    # Каждый поток — своё соединение с БД
    conn = get_connection()
    user_id = ensure_parser_user(conn)
    save_parsed_result(conn, user_id, title, url)
    conn.close()

               for url in URLS]
    t0 = time.perf_counter()
    for t in threads: t.start()
    for t in threads: t.join()
    return time.perf_counter() - t0

🔀 Multiprocessing — парсинг

Каждый URL обрабатывается в отдельном процессе. Соединения с БД нельзя передавать между процессами — каждый создаёт своё. Для I/O задач это избыточно из-за накладных расходов на запуск процессов.

def parse_and_save(url: str) -> dict:
    response = requests.get(url, timeout=10)
    title = BeautifulSoup(response.text, "html.parser").title.string.strip()

    # Обязательно новое соединение — нельзя шарить между процессами!
    conn = get_connection()
    user_id = ensure_parser_user(conn)
    save_parsed_result(conn, user_id, title, url)
    conn.close()
    return {"url": url, "title": title, "status": "ok"}

def main() -> float:
    t0 = time.perf_counter()
    with multiprocessing.Pool(processes=len(URLS)) as pool:
        results = pool.map(parse_and_save, URLS)
    return time.perf_counter() - t0

⚡ Async — парсинг (aiohttp)

aiohttp делает HTTP-запросы асинхронно. asyncio.gather() запускает все запросы одновременно. Запись в БД через синхронный psycopg2 выполняется в ThreadPoolExecutor чтобы не блокировать event loop.

async def parse_and_save(session, url, executor) -> dict:
    async with session.get(url, timeout=ClientTimeout(total=10)) as resp:
        html = await resp.text()               # не блокирует event loop

    title = BeautifulSoup(html, "html.parser").title.string.strip()

    # psycopg2 синхронный — запускаем в executor
    loop = asyncio.get_running_loop()
    await loop.run_in_executor(executor, _save_to_db, title, url)
    return {"url": url, "title": title, "status": "ok"}

async def main_async() -> float:
    t0 = time.perf_counter()

        async with aiohttp.ClientSession() as session:
            tasks = [parse_and_save(session, url, db_executor) for url in URLS]
            results = await asyncio.gather(*tasks)   # все параллельно
    return time.perf_counter() - t0

Общие выводы и анализ

Задача 1 (CPU-bound): победитель — Multiprocessing

Вычисление суммы — классическая CPU-bound задача. Threading не даёт ускорения из-за GIL: только один поток работает в каждый момент. Multiprocessing создаёт отдельные процессы, каждый со своим интерпретатором, что обеспечивает настоящий параллелизм. Async + ProcessPoolExecutor достигает аналогичного результата, но с более сложным кодом.

Задача 2 (I/O-bound): победитель — Async

Парсинг веб-страниц — I/O-bound задача: программа большую часть времени ждёт ответа от сервера. GIL снимается во время I/O, поэтому threading эффективен. Async с aiohttp даёт максимальную производительность: event loop обрабатывает сотни соединений в одном потоке без накладных расходов. Multiprocessing здесь избыточен.

Парсинг сайтов (I/O)✅ ~5x быстрее⚠ ~4x (накладные)✅ ~10x быстрее

Практические рекомендации

Используй multiprocessing для тяжёлых вычислений (машинное обучение, обработка изображений, архивирование). Используй async/await для всего, что связано с сетью или файловой системой. threading — хороший выбор для простых I/O задач или интеграции с синхронными библиотеками.
